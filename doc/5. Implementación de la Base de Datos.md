### Implementación de la Base de Datos ⚙️

En esta sección se especifica el proceso técnico para llevar a cabo la implementación de la base de datos propuesta en uno de los servidores de la **Dirección Regional de Educación de Ayacucho (DREA)**. Se detallan las especificaciones del servidor, los scripts DDL ejecutados y la configuración para el acceso remoto desde un equipo cliente integrado al dominio de la institución.

---

#### Características del Servidor 🖥️

Para el entorno del servidor se adaptó una computadora de escritorio configurada para suplir los requerimientos operativos del sistema:

* **Marca y Modelo:** HP ProDesk 600 G2
* **Procesador:** Intel Core i7-6700
* **Memoria RAM:** 4 GB
* **Almacenamiento:**
  * **Disco Principal (C:):** Western Digital Blue de 500 GB
  * **Disco Secundario (D:):** Western Digital Blue de 1 TB
* **Sistema Operativo:** Windows Server 2022

---

#### Creación de la Base de Datos 💾

Aprovechando la presencia de dos unidades de almacenamiento independientes, se distribuyeron los archivos para optimizar el rendimiento de entrada/salida (I/O):
* **Archivo de datos principal (`.mdf`):** Almacenado en la unidad `C:`
* **Archivo de registro de transacciones (`.ldf`):** Almacenado en la unidad `D:`

```sql
-- Creación de la base de datos
CREATE DATABASE DREA_PAGOS
ON PRIMARY
(
    NAME = 'Drea_Pagos',
    FILENAME = 'C:\DataDrea\pagos\Drea_Pagos.mdf',
    SIZE = 100MB,
    FILEGROWTH = 25%
)
LOG ON
(
    NAME = 'Drea_PagosLog',
    FILENAME = 'D:\LogDrea\pagos_log\Drea_PagosLog.ldf',
    SIZE = 100MB,
    FILEGROWTH = 25%
);
GO
```

---

#### Creación de Esquemas de Base de Datos 🖥️

Se crearon tres esquemas lógicos para segmentar la arquitectura funcional del sistema:

* **Persona:** Contiene las tablas con información del personal asociado a la DREA (nivel magisterial, cargo, régimen laboral, etc.).

* **Boleta:** Agrupa las tablas relativas a los comprobantes de pago (tipos de haberes, descuentos y montos liquidados).

* **Admin:** Aloja las tablas de gestión de usuarios, roles y permisos de acceso al sistema.

```sql
USE DREA_PAGOS;
GO

-- CREACIÓN DE ESQUEMAS
CREATE SCHEMA Persona;
GO
CREATE SCHEMA Boleta;
GO
CREATE SCHEMA [Admin];
GO

```

#### Creación de Tablas 🗒️

Se presentan los scripts DDL correspondientes a las tablas principales del sistema, definiendo tipos de datos, tamaños de columnas y restricciones de integridad (PRIMARY KEY, IDENTITY, CHECK):

```sql
USE DREA_PAGOS;
GO

-- Esquema Persona: Tabla Trabajador
CREATE TABLE Persona.Trabajador
( 
    Trab_ID              INT IDENTITY(1,1) PRIMARY KEY,
    Trab_primerNombre    VARCHAR(30)   NOT NULL,
    Trab_segundoNombre   VARCHAR(30)   NULL,
    Trab_apellidoPaterno VARCHAR(30)   NOT NULL,
    Trab_apellidoMaterno VARCHAR(30)   NOT NULL,
    Trab_dni             VARCHAR(10)   NOT NULL,
    Trab_codigoModular   VARCHAR(20)   NOT NULL,
    Trab_estado          VARCHAR(20)   NOT NULL,
    Trab_fechaNacimiento DATE          NOT NULL,
    Trab_horaSemanal     INT           NULL,
    Trab_situacion       VARCHAR(20)   NOT NULL,
    CONSTRAINT CHK_Trabestado CHECK (Trab_estado IN ('activo', 'cesante', 'sobreviviente')),
    CONSTRAINT CHK_fechaN CHECK (Trab_fechaNacimiento <= CONVERT(DATE, GETDATE())),
    CONSTRAINT CHK_situacion CHECK (Trab_situacion IN ('habilitado', 'suspendido', 'baja'))
);
GO

-- Esquema Boleta: Tabla Pago
CREATE TABLE Boleta.Pago
( 
    Pago_ID             INT IDENTITY(1,1) PRIMARY KEY,
    Pago_fecha          DATETIME       NOT NULL,
    Pago_montoLiquido   DECIMAL(10,2)  NOT NULL,
    Pago_totalDescuento DECIMAL(10,2)  NOT NULL,
    Pago_totalHaber     DECIMAL(10,2)  NOT NULL,
    Pago_montoImponible DECIMAL(10,2)  NOT NULL,
    Pago_seguro         DECIMAL(10,2)  NULL,
    Pago_cFijo          DECIMAL(10,2)  NULL,
    Pago_cVariable      DECIMAL(10,2)  NULL,
    Pago_UserID         INT            NOT NULL,
    Pago_TrabID         INT            NOT NULL,
    CONSTRAINT CHK_montoLiquido   CHECK (Pago_montoLiquido >= 0),
    CONSTRAINT CHK_totalDescuento CHECK (Pago_totalDescuento >= 0),
    CONSTRAINT CHK_totalHaber     CHECK (Pago_totalHaber >= 0),
    CONSTRAINT CHK_montoImponible CHECK (Pago_montoImponible >= 0),
    CONSTRAINT CHK_seguro         CHECK (Pago_seguro >= 0),
    CONSTRAINT CHK_cFijo          CHECK (Pago_cFijo >= 0),
    CONSTRAINT CHK_cVariable      CHECK (Pago_cVariable >= 0)
);
GO

-- Esquema Boleta: Tabla Pago Detalle
CREATE TABLE Boleta.Pago_Detalle
( 
    Pagod_ID           INT IDENTITY(1,1) PRIMARY KEY,
    Pagod_montoParcial DECIMAL(10,2)  NOT NULL,
    Pagod_PagoID       INT            NOT NULL,
    Pagod_HaberID      INT            NOT NULL,
    CONSTRAINT CHK_montoParcial CHECK (Pagod_montoParcial >= 0)
);
GO
```

#### Creación de Relaciones entre Tablas 📗

Para asegurar la integridad referencial del modelo relacional, se vincularon las entidades mediante restricciones de clave foránea (FOREIGN KEY):

```sql
-- RELACIONES DEL ESQUEMA PERSONA
ALTER TABLE Persona.Banco_Cuenta
ADD CONSTRAINT R_30 FOREIGN KEY (BancoC_CuentaID) 
    REFERENCES Persona.Cuenta_Bancaria(Cuenta_ID)
    ON DELETE NO ACTION ON UPDATE NO ACTION;
GO

ALTER TABLE Persona.Banco_Cuenta
ADD CONSTRAINT R_31 FOREIGN KEY (BancoC_BancoID) 
    REFERENCES Persona.Banco(Banco_ID)
    ON DELETE NO ACTION ON UPDATE NO ACTION;
GO

ALTER TABLE Persona.Cuenta_Bancaria
ADD CONSTRAINT R_29 FOREIGN KEY (Cuenta_TrabID) 
    REFERENCES Persona.Trabajador(Trab_ID)
    ON DELETE NO ACTION ON UPDATE NO ACTION;
GO

-- RELACIONES DEL ESQUEMA BOLETA
ALTER TABLE Boleta.Pago
ADD CONSTRAINT R_17 FOREIGN KEY (Pago_UserID) 
    REFERENCES [Admin].[User]([User_ID])
    ON DELETE NO ACTION ON UPDATE NO ACTION;
GO

ALTER TABLE Boleta.Pago
ADD CONSTRAINT R_43 FOREIGN KEY (Pago_TrabID) 
    REFERENCES Persona.Trabajador(Trab_ID)
    ON DELETE NO ACTION ON UPDATE NO ACTION;
GO

ALTER TABLE Boleta.Pago_Detalle
ADD CONSTRAINT R_15 FOREIGN KEY (Pagod_PagoID) 
    REFERENCES Boleta.Pago(Pago_ID)
    ON DELETE NO ACTION ON UPDATE NO ACTION;
GO
```
